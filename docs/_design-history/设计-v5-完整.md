## 0 · 一句话

> **一个药品问答 agent，它的每一步都写进溯源账本。**
> **该不该回答，不是"模型觉得不确定"，而是"账本里有没有证据撑着"。**

**和主流的差别**：

| | 主流做法 | **我们** |
|---|---|---|
| 怎么知道该拒答 | 模型**学会**说"我不知道"（训练）/ 采样一致性给置信度 | **从账本里算**出来 |
| 可解释吗 | ❌"模型觉得不确定" | ✅"这条引用追不到出处" |
| 可验证吗 | ❌ 依赖模型自评 | ✅ **机械可判** |

> 2026.07 周伯文的原话：**"今天的大模型不知道自己不知道什么。"**
> 我们的答案是：**不靠模型自省，靠记账。**

## 1 · 三个差异化（其余都是常规工程）

| # | 差异化 | 一句话 | 为什么别人做不了 |
|---|---|---|---|
| **①** | **章节定位** | 问题 → 直接定位到该查哪一节 | 论文/网页是自由文本，**没有结构可定位**。DailyMed 章节带 LOINC 码 |
| **②** | **溯源判定拒答** ⭐ | 该不该答由**账本的完整性**决定 | 主流全在模型侧（训练/置信度），**没人从证据侧算** |
| **③** | **跨层归因** | 答错了，能指出是检索/利用/推理哪一层的锅 | 组件级指标只能告诉你"零件好不好"，不能诊断 |

## 3 · "完整 agent"的定义 + 架构

```
完整 agent = 输入 → 理解 → 行动 → 观察 → 反思 → 输出 → 记忆
             每一环都有明确契约，整条链路能端到端跑通
```

### 七阶段（线性，不是 DAG）

```
   用户问题
      ↓
   ┌────────────── 证据账本（贯穿，每步都写）──────────────┐
   ↓          ↓           ↓           ↓          ↓       ↓
 ①Guard → ②Understand → ③Retrieve → ④Reflect → ⑤Generate → ⑥Verify
                                                             ↓
                                                       ⑦Memory
```

### 每阶段的契约

| # | 阶段 | 输出（结构化） | **判据** |
|---|---|---|---|
| ① | Guard | `{in_scope, reason}` | 边界集 `out_of_scope` **全拦下** |
| ② | Understand | `{intent, drug, sub_queries[], resolved_query}` | 指代消解**准确率 ≥ 0.9** |
| ③ | Retrieve | `[Chunk]`（rank/score） | **Recall@5 ≥ 0.85**（现已 0.891） |
| ④ | Reflect | `{sufficient, action, missing[]}` | 边界集拒答**准确率 ≥ 0.9** |
| ⑤ | Generate | `{claims:[{text, citations[]}]}` | 引用格式**合法率 100%** |
| ⑥ | Verify | `{valid, invalid[]}` | 注入坏引用**100% 抓住** |
| ⑦ | Memory | 更新后的会话状态 | 多轮**一致率 ≥ 0.9** |

**每阶段都用 schema 约束输出** —— 下游靠这些字段做**机械判断**。

## 4 · 核心数据结构：溯源图

### 三个实体 + 三种关系

```
Step（一步动作）──retrieved──▶ Chunk（说明书片段）
   │                            ▲
   │                            │ cited
   └──generated──▶ Claim ───────┘

关系：retrieved（检索到了）｜ cited（引用为证）｜ derived（由此推出）
```

### 引用契约（**索引建立时就定好，不是模型现编的**）

| 字段 | 作用 |
|---|---|
| `chunk_id` | `{setid}#{loinc}#{序号}` |
| `doc_id` | 哪份说明书 |
| `loinc` | 哪一节 |
| `char_span` | 在原文的**精确位置** |
| `content_hash` | ⭐ **防篡改** |

### 核验 = 机械判断，不问 LLM

```
查 chunk_id 在不在索引  →  查 content_hash 对不对得上
```

### 归因判据（差异化 ③）

```
答错一道题，看账本就知道是哪层的锅：
  检索层  该引的 chunk 没进 top-k        → 改检索
  利用层  进了 top-k 但没写进 claims      → 改生成
  推理层  写进 claims 了但结论错          → 改模型 / 标注 gold 错
```

## 5 · ⭐ 核心实验：拒答机制对照（这是"有意义"的关键）

**命题**：**用溯源判定该不该答，比让模型自评更准、更少过度拒答。**

```
配置 A：LLM 自评      —— 直接问模型"你确定吗 / 有没有把握"
配置 B：账本判定      —— 证据的 claim support 覆盖度低于阈值 → 拒答
配置 C：两者结合      —— A ∧ B

在边界集（~50 条，四类）和端到端集上比：

    拒答准确率      该拒的拒了没有
  ★ 过度拒答率      不该拒的拒了没有    ← 关键指标
    漏答率          该拒的没拒
    可解释性        B/C 能给出"为什么拒"，A 不能
```

**预期**（要实测，这是假设）：
- A 的**过度拒答率**高（模型倾向于"不懂就拒"或"硬答"）
- B 的**可解释性**最好，但对"推理层错误"无能为力
- C 兼顾

**这个实验能跑出数字，而且有 Trade-off 可讲。**

## 6 · 语料与评测集

### 语料：6 份药 → **50 份药**

```
理由：① 评测集不重复  ② 泛化性讲得出口
来源：DailyMed API（已验证可达、免认证、有分页）
规模：50 药 × ~6 节 ≈ 300 节 ≈ 1200 chunks
成本：100 个请求 × 2 秒 ≈ 5 分钟，零 GPU
```

### 评测集：~220 条，**分布在 50 份药上**

| 集 | 条数 | 测什么 | 反重复约束 |
|---|---|---|---|
| `retrieval` | ~70 | 召回（direct / paraphrase 两档） | 每个 (药,章节) 最多 2 题 |
| `section_locate` | ~70 | 问题 → LOINC | 同上 |
| `boundary` | ~50 | 四类边界（越界/越范围/没这药/没这节） | 不依赖药量 |
| `e2e` | ~30 组 | 全链路 + 指代消解 + 记忆 | 每组不同药 |

**✅ 硬约束：同一个 (药, 章节, 意图) 组合最多出现 2 次。**
（这是"不冗杂"的量化定义，自检脚本会断言它）

### 指标

```
Recall@5 ｜ MRR ｜ 定位准确率 ｜ 拒答准确率 ｜ 过度拒答率
引用准确率 ｜ Pipeline Success Rate ｜ ⭐ 跨层归因分布
```

## 8 · ⛔ 不做什么（每条都答过"不做会怎样"）

| 不做 | 为什么 |
|---|---|
| 多智能体 / Red-Blue 对抗 | 我们的错误来源是"证据不够"，不是"观点冲突" |
| DAG 编排 | 七阶段是**线性**的，没有并行分支 |
| 知识图谱 / GraphRAG | 说明书是**扁平章节结构**，没有实体关系需要图 |
| 上下文三级压缩 | 对话最长 4 轮，**撑不爆上下文** |
| 多后端热切换 | 只需 1 个 LLM，那是演示需求不是研究需求 |
| 训自己的 LLM | 训练侧是**项目一**。项目二定位是系统侧（零 GPU） |
| 通用深度研究 | 那是参考项目场景。我们做药品——**答案封闭、可机械判定** |

**可选的加码（主线做完再考虑）**：
① 微调检索器（BGE-M3）—— 唯一的 GPU 用武之地，天然有"从 X 到 Y"

## 10 · 诚实边界（写进报告，不许含糊）

1. **概念框架参考 arXiv 2606.04990**，不是我们提出的。增量是 §1 那三条。
2. **`content_hash` 只能证明"这句话来自这里"，不能证明"推论是对的"**
3. 语料 50 份药，仍非全库，泛化性有限
4. 问题是我们自己造的（手写 + 从语料反向生成），**有自造偏差**
5. LLM 用 API，换模型结果会变 —— 但这恰好说明"**harness 决定了下限**"
6. **不做训练**（系统侧项目）
