# 块 E12 前置 · 决策信号探针 —— 实测报告

> 2026-09-18 晚 ｜ 判据 `scripts/eval_decision_signal.py` ｜ 原始输出 `reports/E12prep-decision-signal.txt`
> **一句话：E12「该不该训」这个问题的答案，在当前生成器上答不了 ——
> 它从 0.00 到 0.41 全凭池序。而这个"答不了"本身就是今晚最值钱的产出：它省下的是 GPU 时。**

---

# 一、为什么要先做这一步

设计 v7 里策略③是「用 ①② 的决策日志 **SFT 小模型**」，5 GPU 时。

但在花 GPU 之前必须先答一个问题：

> **这些决策点里，有多少是「选什么动作都一样」的？**

因为决策日志里的标签是**"当时那套规则碰巧选了什么"**，不是"这是对的"。
没有梯度的决策点，模仿它 = 把规则的巧合记下来，换批题就失效。

ToolHorizon 已经栽过一次同形的坑（**40% 的题的 reward 与策略无关**）。
**E12 的开工判据就应该是"这里有没有同样的病"，而不是"训完看看效果"。**

---

# 二、交付了什么

| 产物 | 作用 |
|---|---|
| `agent/decisions.py` · `LoggingPolicy` | 包住任意策略，把每个决策点的 (状态特征, 动作) 记下来。**不改变被包策略的行为** |
| `agent/decisions.py` · `ForcedPolicy` | 在第 i 个决策点**强制换动作**，其余交给原策略 → 反事实重放 |
| `agent/decisions.py` · `state_features` | 状态 → **机械可判**的特征向量（覆盖度是算的、定位命中是比字段） |
| `scripts/eval_decision_signal.py` | 闸门：四张表 + 5 条断言 |
| `data/decisions.jsonl` | 478 个决策点 |

⭐ **为什么反事实能成立**：循环是确定性的（同 seed、无随机、无时间），
所以第 i 步之前的状态与基线轨迹**逐字节一致** ——
在第 i 步强制换动作，等价于"在同一条轨迹的同一个岔口拐另一条路"。

**边界（写进报告）**：换的是**动作类型**，参数用规范默认值；
"换动作"和"换参数"是两件事，本块只量前者。

---

# 三、⚠️ 第一版判据是套套逻辑（自己抓到的）

第一版用「**结局变没变**」当有梯度的定义。跑出来是这样：

```
基线答对的题：有梯度 412/412 = 1.000
基线答错的题：有梯度   0/ 66 = 0.000
```

**太干净了 —— 干净到假。** 原因：反事实候选里含 `abstain`。
任何一条答对的轨迹，随便哪一步强制拒答 → 没有引用 → 结局必然变错。
于是"有梯度"对每条正确轨迹的**每一个**决策点恒真。

> **它量的是"拒答会不会搞砸"，不是"这一步重不重要"。**

**修法**：把单向的"变了没"换成**双向**的：

```
better_exists   当时做错了，换个动作**能对**吗   ← 这才是可学信号
worse_exists    当时做对了，换个动作**会错**吗
```

修完之后的第一个自检就抓到了残留：
**答对的题上 `better_exists` 必须恒为 0**（结局已经是最好的了，不可能更优）——
实测 0，符合定义。而 `worse_exists` 在答对的题上恒为 **1.000**，
**这一条是 abstain 造成的，不是发现**，报告里必须这么写。

# 四、实测结果

## ② 动作分布（**不报这一张，模仿准确率就是骗人的**）

```
策略        决策点    最常见动作        分布
rule         240     search (0.50)   search:120  locate:60  answer:60
coverage     238     search (0.52)   search:124  locate:60  answer:54
```

**动作分布没有偏斜到"全猜一个"**（0.50 / 0.52 < 70% 警戒线）。
⇒ 但这条的用处是**给模仿准确率立基线**：以后任何人报"模仿准确率 85%"，
**必须和 0.52 比，不是和 0 比。**

## ③ 反事实：这一步重不重要

```
正序：
  基线答对的题（412 个决策点）：有更优 0 (0.000)  ｜ 有更差 412 (1.000)
  基线答错的题（ 66 个决策点）：有更优 0 (0.000)  ｜ 有更差   0 (0.000)

倒序：
  基线答对的题（364 个决策点）：有更优 0 (0.000)  ｜ 有更差 364 (1.000)
  基线答错的题（114 个决策点）：有更优 15 (0.132) ｜ 有更差   0 (0.000)
```

## ④ ⭐⭐ 错题的可救回率 = **E12 的提升空间上界**

| 池序 | 策略 | 答错 | 换一步能改结局的 | 可救回率 |
|---|---|---|---|---|
| 正序 | rule | 8 | **0** | **0.00** |
| 正序 | coverage | 8 | **0** | **0.00** |
| 倒序 | rule | 15 | 7 | **0.47** |
| 倒序 | coverage | 12 | 4 | **0.33** |

```
正序合计  0/16  = 0.00   ⇒ 任何策略在这批题上都不可能比现在更好，训练的上界是"打平"
倒序合计 11/27  = 0.41   ⇒ 四成的错题，换个动作就对了
```

# 五、⭐⭐ 结论：E12 的开工判据**当前答不了**，而这正是要报的

**同一个判据，正序说 0.00、倒序说 0.41。** 差的不是一个零头，是"该不该花 GPU 时"。

## 为什么正序是 0.00 —— 这个数不是噪声，它有明确含义

正序下那 16 个错题决策点，**换任何动作都救不回来**。为什么？

因为那 8 道错题**全部病在生成层**（E13b 的探针已经逐条量过）：
gold 与问题字面零重合 → mock 按字面重合挑，**必然**挑错。
**换策略的动作改不了生成器的判据** —— 所以 0 是真的。

⇒ 这与 E6 的「瓶颈搬层」（retrieval 0 / utilization 8）**是同一件事的两种说法**：
**病在利用层，不在策略层。**

## 为什么倒序又是 0.41

倒序把一批**本来对的题**弄错了（52 → 45/48），而这批新错误的机制不同 ——
它们来自"池子顺序"，是**动作可影响的**，所以救得回来。

## ⇒ 由此得到的真结论

> **在 GroundedMockLLM 上，E12 的提升空间无法稳定估计 ——
> 因为"错误从哪来"这件事本身被池序决定。**
>
> **训练一个策略去拟合一个顺序敏感的目标，学到的只会是顺序的巧合。**

**⇒ 行动：E12 的"按下训练"这一步，必须等真模型（或可靠奖励信号），
现在训 = 拿 5 个 GPU 时去拟合 mock 的 tie-break。**

**⇒ 但前置不是白做**：决策日志、特征、反事实工具链全部就位；
**接上真模型后，改一个 `make_llm()` 就能重跑这张表** —— 那才是 E12 真正的开工信号。

凡是"因为指标 X 达到了阈值，所以下一步做 Y"的决定，
**X 必须先过一次对抗变换。**

# 七、诚实边界

1. **生成器仍是 `GroundedMockLLM`** → 见 §五，这是本块结论的**唯一**约束。
2. **反事实只换动作类型，不换参数**。
3. **单步反事实不是因果推断**：改了第 i 步，第 i+1 步的状态就变了，
   量的是**策略 + 环境的联合反应**，不是控制变量。
4. **样本小**：正序只有 16 个错题决策点，倒序 27 个。**0.00 与 0.41 的差距
   有相当一部分是样本量 + 池序共同造成的**，别把 0.41 当成精确值。
5. **`worse_exists` 在答对的题上恒为 1.000 是 abstain 造成的**，不是发现（见 §三）。
