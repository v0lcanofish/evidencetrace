# 二、修的那个 bug：乘法加成 = 把强先验挂在弱信号上

原实现在 `BM25Retriever.search_detail`：

```python
scores[i] = scores.get(i, 0.0) * locate_boost      # ← 乘性
```

而 `ChunkBM25.search()` 里有一句 `if s > 0` —— **BM25 分为 0 的块压根不进候选榜**。

```
实测：平均每题 1063 / 1156 个块（92%）BM25 分为 0
⇒ 0 × 3 = 0
⇒ 定位层只能给「BM25 已经捞到的块」重新排序，
   永远引不进 BM25 漏掉的块 —— 而它要修的恰恰就是那些。
```

**检索集 8 道错题，全部是这个原因**：定位**指对了**章节，
gold 块的 BM25 分是 0，于是定位再准也白搭。

> **教训：乘法加成 = 把强先验挂在弱信号上。**
> **先验要能「引入候选」，不能只做「重排序」。**

# 三、三路候选 + 自适应权重（权重是算出来的，不是拍的）

```
S  结构先验   定位章节内的块（**含 BM25 零分块**）—— 医学编码是先验事实
B  词面      全局 BM25 榜
D  语义      全局稠密榜（bge-small-en-v1.5，384 维，mean pooling + L2 归一化）
```

## ⭐ 为什么不能用等权 RRF

实测：**等权 RRF 会把稠密拉低**（探针 test：稠密单独 0.717 → 等权融合 0.633）。

原因量出来了——**词面和语义的强弱不是固定的，取决于查询里有没有判别性实词**：

| 查询类型 | BM25 | 稠密 | 谁赢 | n |
|---|---|---|---|---|
| 检索集·**有实体**（实体词是真 token） | **0.950** | 0.850 | BM25 | 40 |
| 检索集·**无实体**（只剩药名+疑问词） | 0.100 | **0.700** | 稠密 | 20 |
| 探针 test（意图词不认识） | 0.467 | **0.717** | 稠密 | 60 |

机制很直白：**药名在该药的每个 chunk 里都有**，
所以只剩药名时，BM25 在**药内**排序基本是噪声。

## 权重怎么算

用 `contrast_p90(q)` —— **BM25 自己的分数分布有多尖**，纯机械量、无自由参数：

```
contrast_p90 = (top1 分 − 第 10 名的分) / top1 分
```

分辨力实测（BM25 自己的 Recall@5）：`<0.2 → 0.22` ｜ `0.2~0.5 → 0.53` ｜ `≥0.5 → 0.95`

> 和覆盖度那条是**同一个思路**：**"够不够"要算出来，不能让模型自己感觉。**

## 结构先验那一路：强权重，但**不做硬限定**

`section_weight` 默认 3.0。**不设成 restrict 是有意的**：定位**错**的时候，
限定会把 5 个位置全浪费掉；给强权重，让定错的章节靠自身融合分自然沉下去。

> ⚠️ **诚实边界**：现有评测集里定位**要么全对（检索集 60/60）、要么全不触发（探针 120）**，
> **没有"定位触发但指错了"的题** → 这个权重在失败模式上的表现**测不出来**，只能靠机制论证。

# 四、重排：必须**带硬约束**，否则是负收益

探针 test 上三路融合的 Recall@k 曲线：

```
@1  0.433     @5  0.717  ← 交付给 agent 的就到这里
@10 0.867     @20 0.933
@50 1.000
```

**@5 和 @20 差 0.216** —— gold 已经在候选里，只是名次不够。这正是重排的活。
（如果 @20 ≈ @5，说明漏在**召回**，那该动的是候选生成，重排白搭。）

```
⑤ +重排（带硬约束）  探针 test 0.783 ≥ ④ 0.700   ✓ 不劣化
⑤ +重排（不带约束）  检索集 1.000 → 0.850        ✗ 负收益，60 条里 46 条混进别的药
```

**不限定就上重排 = 让交叉编码器把结构先验洗掉。**

# 五、⭐ 方法论发现：**这把尺子到顶了**

```
检索集 60：章节定位 **60/60 全对**
⇒ 命中判据只比 (药, 章节)
⇒ **任何「定位优先」的架构都按构造拿满分**
⇒ 实测 ③ 三路融合 / ④ +稠密 / ⑤ +重排 **全是 1.000**
```

**Recall@5 这张表已经不量检索质量了，它量的是定位准确率。**
稠密加进来也量不出贡献 —— **不是它没用，是这把尺子量不到。**

## 于是造了探针集（120 条，dev 60 / test 60）

**结构先验 = 「识别出药 + 识别出意图 → 查哪一节」。**
探针**仍然给药名**（否则就不是检索问题，是指代消解问题，那是 E10 的活），
**只把意图词换成关键词表里没有的说法**：

```
drug 识别得到 → intent 识别不到 → loincs=[] → 先验失效 → 退回纯检索
```

**度量与检索集完全一致**（Recall@5 over (doc, loinc)），唯一变的是"先验在不在"
→ 两张表的数字可以直接比。

### dev / test 协议（回答"那我把词表补全不就行了？"）

这是个一定会被问到的问题，所以**用实验回答，不能嘴上回答**：

```
dev  档  允许拿它去**补 LOCATE_RULES 关键词**（模拟"人工枚举"）
test 档  **换一套完全不同的问法**，补完词表后不许再动
```

| 探针档 | ① BM25 | ③ 三路融合(无稠密) | ④ +稠密 | ⑤ +重排 |
|---|---|---|---|---|
| dev（可调参） | 0.467 | 0.400 | 0.700 | **0.833** |
| test（只报不改） | 0.467 | 0.467 | 0.700 | **0.783** |

**补词在 dev 上救回来多少、在 test 上救回来多少 —— 这个差就是枚举法的天花板，
是量出来的，不是猜的。**

# 六、⭐⭐ 副作用（最值钱的一条）：**瓶颈搬层**

> 检索层修好后，**agent 侧 14 处写死 `BM25Retriever` 的调用点被收成一个工厂**
> （`retrieval/factory.py`）—— 否则"新检索器有测试有数字，只有主路径没变"。

**全部判据在换完检索器后重跑（E7 / E8 / E9 / E10 / E11 / E13 全过）。**
其中 E13 出现了一个**必须报告**的翻转：

**同一批 60 条题、同一个循环、同一个策略、同一个生成器，只换检索器：**

| 配置 | retrieval | utilization | reasoning | none |
|---|---|---|---|---|
| ① 旧 BM25（乘性 boost） | **8** | 0 | 0 | 52 |
| ② 新混合（三路 + 重排） | **0** | **8** | 0 | 52 |

**⭐ 而且失败的是完全同一批题**（交集 8/8，已锁进判据 `eval_attribution.py` ⑥）。

```
旧口径那 8 条：gold 章节**没被召回**      → 病在检索
新口径那 8 条：gold 章节**召回了，没进回答** → 病在利用
```

**⇒ 检索层的病不是被治好了，是被推到下一层了。**
**⇒ 归因指出的下一步动作是「改上下文压缩 / 排序」—— 这是算出来的，不是拍的。**

## 那 8 条到底怎么回事（`scripts/diag_utilization_cases.py` 逐条看现场）

拆开之后发现它**混着两种完全不同的情况**，正确动作不同，不能合成一个数：

| | 条数 | 现场 | 病根 |
|---|---|---|---|
| ① **引了另一节** | 5 | 证据池里 10 条、gold 在其中，生成层挑了**别的节**去引 | 生成前**没有任何排序/剪裁**，证据池**只增不减** |
| ② **两层判据打架** | 3 | **覆盖度算出 1.00、槽位一个不缺**，生成层却说"证据不足" → 拒答 | 覆盖度是**词面**槽位，生成器用的是**另一套**词面判据 |

> ⚠️ **② 必须单独记**：`attribute()` 的 correct 判据是 `gold ⊆ cited`，
> **拒答没有引用 → 必然落进 utilization 分支**。
> 不拆开就会拿一个混口径的数去指导改进。（脚本里已经把这 3 条标出来了。）

⚠️ **诚实边界**：生成层仍是 `GroundedMockLLM`（**照证据抄**，
按"与问题实词的词面重叠"打分、同分取证据池靠前那条）。
所以**"8"这个数依赖生成器**，接真模型后会变。
但**"证据池只增不减、生成前无排序/剪裁"是系统的事实，与生成器无关** ——
这是一条可以独立于 mock 讨论的、下一步该做的改进。

# 九、诚实边界（写进报告）

1. **探针模板是手写的**，不是真人问法；每类意图只有 4 种说法 →
   用途是"量先验失效时的检索能力"，**不是"模拟真实分布"**。
2. **"定位触发但指错了"的题一条都没有** → `section_weight` 在失败模式上测不出来。
3. **域外弃权漏放 2 条**（`Write me a Python function to sort a list.` /
   `What time is it in New York?`）→ 稠密余弦门限 τ=0.60 挡不住这两类。
4. **生成层仍是 mock** → utilization 那 8 条的数字依赖生成器（见 §六）。
5. **检索集已经饱和**（1.000）→ 后续改进**只能看探针集**，别再拿检索集的数报进展。
