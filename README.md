# EvidenceTrace

> **一个药品咨询 agent：它自己决定每一步做什么；每个决定都要过机械检查 ——
> 报告里每一条引用，都要能追溯到真实存在的证据块。**

语料是 FDA 药品说明书（DailyMed）。和通用 RAG 的区别不在于「检索得更准」，
而在于**回答里每句话的出处是**事实判断**，不是语义判断** —— 引用对不上，就是错的，不需要人来判。

---

## 一、为什么是药品场景

用药咨询答错的代价是**医疗 + 法律**双重风险，而 FDA 说明书是法定文件。
这逼出三个在通用问答里不成立的设计：

| 场景性质 | 逼出什么 |
|---|---|
| 说明书**写什么就是什么**，不是开放讨论 | 要**精确命中某一节**，不要"多视角综合" |
| 答错可能害人 | **拒答是核心能力**，不是失败 |
| SPL 章节带 **LOINC 医学编码** | ⭐「该查哪一节」变成**机械可判** |

最后一条是本项目的地基。它把「检索」从"猜哪段文字相关"变成：

```
"能不能一起吃"  →  DRUG INTERACTIONS   (LOINC 34073-7)
"吃多少"       →  DOSAGE AND ADMIN  (LOINC 34068-7)
"孕妇能吃吗"    →  PREGNANCY
```

**按结构定位，不是按语义猜**，而且可解释：「我引了相互作用那节，因为你在问能不能一起吃。」

## 二、核心：把控制流交给策略

```
状态  s = (q, E, T, b)     问题 ｜ 已收集证据 ｜ 试过的动作 ｜ 剩余预算
动作  a ∈ { locate, search, ask, answer, abstain }
策略  π(a | s)
```

循环本身**不认识任何策略**：它只认 State，不给任何捷径。
所以「规则 / 覆盖度 / 训练」三档可以**共用同一个循环**，差异全部归因到策略头上。

```
agent/policy.py     RulePolicy        0/1：有证据就答
                    CoveragePolicy    算出来的覆盖度 ≥ 阈值才答
                    (TrainedPolicy)   —— 见 §五，前置已就位
agent/loop.py       循环 + 四个刹车
agent/state.py      状态契约（循环和策略唯一的公共接口）
```

### 四个算法点

**① 章节定位（检索层）** — `retrieval/`

三路候选：结构先验（定位章节内的块）｜ 词面（BM25）｜ 语义（稠密）。
融合权重用 `contrast_p90`（BM25 分数分布的尖锐度）**算出来**，无自由参数。

> ⚠️ 这里修过一个关键 bug：原实现是 `score *= locate_boost` 的**乘法加成**，
> 而 BM25 分为 0 的块压根不进候选榜（实测平均每题 **92%** 的块 BM25 分为 0）。
> **`0 × 3 = 0` —— 定位只能重排，永远引不进它本来要修的那些块。**
> 教训：**先验要能「引入候选」，不能只做「重排序」。**

**② 覆盖度与停止准则（策略层）** — `agent/coverage.py`

不问 LLM「你觉得够了吗」——**槽位机械可判**：
药品槽位（证据里有没有问题点名的那份药）｜ 章节槽位（有没有来自定位到的那一节）｜
实词槽位（这个词在**该药**的证据正文里出现了吗）。

> ⚠️ 两个自己造出来又修掉的漏洞：
> ① **「缺什么查什么」会自己满足自己** —— 缺 `stomach` 就拿 `"take stomach"` 去查，
>    查回来当然有 → 槽位填上 → 覆盖度涨 → 作答。**停止准则形同虚设。**
> 修法：判定范围收窄到「问题点名的那份药」。
> ② **确定的「没有」不该和「还不够」用同一个量纲** ——
>    「问的是我们没采的那一节」是**事实**，摊进分数会被别的槽位抬起来 → 做成硬信号 `hard_fail`。

**③ 契约引用与机械核验（生成层）** — `agent/verify.py`

引用格式 `[<setid>#<loinc>]`，核验**跑在循环内部**：答案生成后先过核验，
不过就作废、把失败写进 `AgentState.failed_cites`，**策略读得到** → 去补检索；补不到 → 拒答。

> ⭐ **核验的边界必须说清楚：闭包验的是出处真实性，不是相关性。**
> 问 `Can I take aspirin if I have a stomach ulcer?`（aspirin 不在语料里）：
> 规则策略引的 5 条证据**一条都没提 aspirin**，而**闭包检查全部通过** ——
> 因为每条引用确实都追得到出处。
> **「引用追得到」≠「引对了」。**

**④ 生成前的证据选择 + 跨层归因** — `agent/select.py` / `ledger/`

归因是**链式的**：第一个不达标的层就是病根，不是"哪层分最低"。

## 三、实测数字

> ⚠️ **先读这段再读数字**：生成层目前是 `GroundedMockLLM`（照证据抄的离线生成器），
> **不是真模型**。真模型接入点已写好（`agent/llm.py`，带磁盘缓存），换一个 key 即可重跑。
> 另外：**方向性结论可以报，绝对数字必须附对抗变换**（见 §四）。

| 项 | 数字 |
|---|---|
| 语料 | 50 份药 / 297 节 / **1111 chunk**（其中 10 个曾经因 id 撞车被静默覆盖，已修） |
| 检索集 60 Recall@5 | 0.867 → **1.000** |
| **探针集 test 60** Recall@5 | 0.467 → **0.783**（先验失效时的纯检索能力） |
| 端到端答对率 | **0.867**（规则 0.867 → 覆盖度 0.867，**持平**） |
| **硬答率**（证据不足却作答） | 0.778 → **0.044** |
| **拒答准确率** | 0.222 → **0.956** |
| 坏引用拦截 | **10/10**，含 2 条反向用例（好引用不许误伤） |

⭐ **最值钱的一条结果：瓶颈搬层。**
同一批 60 题、同一个循环、同一个策略，**只换检索器**：

| 配置 | retrieval 层错 | utilization 层错 |
|---|---|---|
| 旧 BM25（乘法加成） | **8** | 0 |
| 新混合（三路 + 重排） | **0** | **8** |

失败的是**完全同一批题**（交集 8/8，已锁进判据）。

> **⇒ 检索层的病不是被治好了，是被推到下一层了。**
> **⇒ 归因给出的下一步「改生成前的证据排序/剪裁」是算出来的，不是拍的。**

## 四、⚠️ 一条从踩坑里长出来的纪律

在上面那个 mock 生成器上，**绝对数字对输入顺序敏感**。
同一批 60 题、同一个策略、同一个生成器，**只把检索返回顺序倒过来**：

```
答对率        52/60 → 48/60
utilization      8  → 12
```

**方向性结论（"病从检索层搬到利用层"）正序倒序都成立；绝对数字不成立。**

> **纪律：报绝对数字之前，先做一次对抗变换（最便宜的是把输入顺序倒过来）。
> 提升消失 ⇒ 那个"提升"是生成器的性质，不是系统的性质。**
> 这条纪律后来还救了一次「该不该花 GPU 时」的决策 —— 见 §五。

量「这些决策点里有多少是选什么都一样的」：

```
错题的「策略可救回率」= 训练的提升空间上界
   正序  0/16 = 0.00     倒序  11/27 = 0.41
```

**同一个判据，正序说"别训"、倒序说"训"。** 差的不是一个零头，是 5 个 GPU 时。

> **⇒ 结论：训练一个策略去拟合顺序敏感的目标，学到的只会是顺序的巧合。
> 策略③ 的"按下训练"必须等真模型，现在训 = 拿 GPU 时去拟合 mock 的 tie-break。**

## 六、Quickstart

**核心链路不需要神经网络**（只有 `numpy`）：

```bash
pip install numpy

# 跑一遍端到端（离线，不联网、不花钱）
python scripts/run_mock.py

# 各项判据（每条都有断言，全过才算数）
python scripts/eval_retrieval.py        # 检索层
python scripts/eval_agent.py            # agent 循环 + 工具集（58 条断言）
python scripts/eval_coverage.py         # 覆盖度 + 停止准则（含 θ 标定）
python scripts/eval_verify.py           # 引用核验
python scripts/eval_session.py          # 多轮一致
python scripts/eval_consistency.py      # 冲突消解
python scripts/eval_attribution.py      # 跨层归因（含"瓶颈搬层"判据）
python scripts/eval_select.py           # 生成前证据选择
python scripts/eval_decision_signal.py  # 策略③ 的开工闸门
```

### 接真模型

```bash
pip install openai python-dotenv
echo "DEEPSEEK_API_KEY=sk-..." > .env
python -c "from agent.llm import make_llm; print(make_llm()('hello'))"
```

`agent/llm.py` 与 `agent/mocks.py` **签名相同、可直接互换**：
带 **temperature=0** 与**磁盘缓存**（同一 prompt 第二次问不花钱，且保证复现），
缺 key 时**直接报错而不是静默降级成 mock** ——
静默降级是最坏的情况：你以为在跑真模型，其实在跑假的，然后拿一堆假数字下结论。

### 完整依赖

`requirements.txt` 分三层（必需 / 出图 / 稠密检索）：
**只有 `numpy` 是必需的**；`torch` + `transformers` 只在走三路融合时才需要，
而且它们在代码里是**惰性 import** —— 不装会自动退回 BM25 + 章节定位。

## 八、诚实边界

1. **生成层是离线 mock**，所有端到端数字依赖它（见 §三、§四）。
2. **语料是 50 份药，不是全库**；问题为自造，有分布偏差。
3. **`content_hash` 只证明"出处真实"，不证明"推论正确"**。
4. **探针集模板是手写的**，用途是"量先验失效时的检索能力"，不是"模拟真实分布"。
5. **没有"定位触发但指错"的样本** → 相关权重在失败模式上测不出来。
6. **域外弃权漏放 2 条**（稠密余弦门限挡不住）。
